مستويات الأولوية

تُستخدم العلامات التالية داخل الخطة:

  • [أساسي]: لا يُنصح بتجاوز الموضوع قبل القدرة على تطبيقه عمليًا.
  • [متقدم]: مطلوب للتعامل مع تطبيقات كبيرة أو للوصول إلى مستوى هندسي متقدم.
  • [تكميلي]: مفيد، لكن لا ينبغي أن يؤخر إتقان المسار الأساسي.
  • [قديم/توافقي]: مهم لفهم وصيانة المشاريع الحالية أو القديمة، وليس بالضرورة الخيار الأول عند إنشاء مشروع جديد.
  • [حسب الحاجة]: يتحدد بأهداف التطبيق ومجال عمله.

مبادئ تنظيم التعلم

  1. تعلّم المفهوم ثم استخدمه: لا تحفظ قائمة APIs من دون بناء شيء يستفيد منها.
  2. التطبيق مبكرًا: بعد كل مجموعة مترابطة من المفاهيم نفّذ تمرينًا أو ميزة صغيرة.
  3. لا تتعلم كل المكتبات دفعة واحدة: أتقن المفاهيم الأساسية أولًا، ثم قارن البدائل.
  4. استخدم التوثيق الرسمي: تعلّم البحث في Android Developers وKotlin Documentation ومرجع المكتبة التي تستخدمها.
  5. حدّث الأدوات بعقلانية: استخدم إصدارات مستقرة ومتوافقة من Android Studio وJDK وKotlin وGradle وAndroid Gradle Plugin والمكتبات. لا تنسخ إصدارات قديمة من درس قديم من دون التحقق من توافقها.
  6. لا تخلط بين الإلمام والإتقان: معرفة اسم RxJava أو Koin لا تعني ضرورة استخدامها في كل مشروع.
  7. اجعل Git حاضرًا منذ اليوم الأول: كل مشروع وتمرين مهم يُحفظ في مستودع Git مع رسائل Commit مفهومة.

نصائح مهمة لتجنب التعلم غير الفعال

لا تجعل حفظ الموضوعات هدفًا

لا يلزم أن تحفظ جميع دوال Kotlin أو Android APIs. المطلوب أن تفهم المفهوم، وتعرف متى تستخدمه، وتستطيع الوصول إلى التوثيق الصحيح.

لا تبدأ بـ Clean Architecture ثقيلة

ابدأ بطبقتي UI وData، وأضف Domain Layer وUse Cases عندما يوجد منطق مشترك أو تعقيد يبرر ذلك. لا تحول كل عملية CRUD بسيطة إلى عشرات الملفات.

لا تجعل كل شيء داخل ViewModel

ViewModel مناسب لحالة الشاشة والتنسيق بين الواجهة والطبقات الأخرى. لا ينبغي أن يتحول إلى مكان لكل منطق الأعمال أو التعامل المباشر مع كل مصادر البيانات.

لا تستخدم GlobalScope كحل افتراضي

اربط Coroutine بالـ Scope المناسب ودورة الحياة المناسبة، وراعِ Structured Concurrency وCancellation.

لا تحجب Main Thread

أي عمل I/O أو حساب مكلف يجب أن ينفذ خارج Main Thread عبر تصميم مناسب، مع إعادة النتائج إلى الواجهة عبر آليات الحالة والتدفق.

لا تعتبر كل Background Task متشابهة

  • Coroutine لعمل مرتبط بعمر عملية أو شاشة أو Scope محدد.
  • WorkManager لعمل مؤجل ومستمر يجب أن يبقى مجدولًا عبر إغلاق التطبيق أو إعادة تشغيل الجهاز وفق قيود النظام.
  • Foreground Service لعمل ظاهر للمستخدم ويتطلب تشغيلًا مستمرًا في حالات تدعمها السياسات.

لا تضع الأسرار داخل تطبيق الهاتف

أي قيمة مدمجة داخل APK يمكن استخراجها بدرجات متفاوتة. لا تخزن Private Backend Secrets داخل التطبيق. استخدم Backend للتحكم في العمليات الحساسة، واحمِ الرموز والبيانات وفق متطلبات التهديد.

لا تستخدم Certificate Pinning بلا سبب

قد يؤدي سوء تطبيقه إلى تعطيل الاتصال عند تدوير الشهادات أو تغير البنية. استخدمه فقط بعد دراسة نموذج التهديد ووضع خطة موثوقة للتحديث والاستثناءات.

لا تعتبر Offline-first مجرد Cache

يحتاج Offline-first إلى تحديد مصدر الحقيقة، وسياسة الكتابة والمزامنة، والتعامل مع التعارضات والفشل وإعادة المحاولة.

لا تفرط في استخدام Multi-Module

ابدأ ببنية بسيطة. أضف Modules عندما تساعد على عزل المسؤوليات أو تسريع البناء أو تمكين فرق متعددة أو إعادة استخدام حقيقي.

تعلم الاختبار منذ البداية

لا تؤجل الاختبارات إلى نهاية المنهج. اختبر الدوال والـ Repositories وViewModels والواجهات كلما تعلمت طريقة جديدة لإدارة السلوك.

لا تحسّن الأداء بالتخمين

قِس أولًا، حدد عنق الزجاجة، ثم غيّر شيئًا واحدًا، وأعد القياس. استخدم Profilers وBenchmarks حيث تناسب.

راقب التوافق والإصدارات

تأكد دائمًا من توافق JDK وGradle وAndroid Gradle Plugin وKotlin وCompose Compiler Plugin وSDK Libraries. استخدم مستندات الإصدارات الرسمية، ولا تنسخ أرقام إصدارات من هذه الخطة باعتبارها ثابتة.

راجع سياسات Google Play قبل الإطلاق

متطلبات Target API Level وسياسات الخصوصية والصلاحيات والـ SDKs تتغير. تحقق من السياسة الفعلية في وقت الإصدار، وليس من مقال قديم أو معلومة محفوظة.
