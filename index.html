How to Study Each Topic

  1. ConceptsUnderstand the problem a concept solves, its terminology, boundaries, and nearby alternatives.
  2. Syntax & APILearn the essential syntax and APIs, then work through official examples. Learn how to find documentation instead of memorizing every function.
  3. Mental ModelUnderstand lifecycle, threading, state, data flow, and guarantees behind the abstraction when relevant.
  4. ExamplesStart with a small example, modify it, and test edge cases and failures.
  5. Practical ExerciseSolve an exercise without copying a solution and explain why your approach is appropriate.
  6. Mini FeatureTurn the idea into a runnable feature, use Git, and document how to run it.

Engineering Guardrails

  • Do not memorize APIs as the goal. Understand the concept, know when it applies, and know how to find its official reference.
  • Keep Git from day one. Put meaningful exercises and every project in a repository with clear commits and a reviewable history.
  • Document important decisions. Write a README for each project and an ADR when a decision has meaningful alternatives or long-term consequences.
  • Do not start with heavy Clean Architecture. Begin with clear UI and data boundaries; add a domain layer or use cases when shared logic or complexity justifies them.
  • Do not put everything in a ViewModel. Use it for screen state and coordination, not as a container for every business rule and data source.
  • Respect structured concurrency. Avoid GlobalScope as a default, propagate cancellation, and never swallow CancellationException.
  • Keep the main thread responsive. Run I/O and expensive computation off the main thread using an appropriate dispatcher or system API.
  • Choose background execution deliberately. Use coroutines for scoped work, WorkManager for deferrable persistent work, and foreground services only for qualifying user-visible ongoing work.
  • Do not embed backend secrets in the app. Anything packaged in an APK can be extracted. Keep private credentials on a backend and protect user tokens and data according to the threat model.
  • Do not add certificate pinning by reflex. Introduce it only with a clear threat model and an operational plan for certificate rotation and recovery.
  • Offline-first is more than caching. Define a source of truth, write policy, synchronization behavior, retry strategy, and conflict resolution.
  • Do not overuse multi-module architecture. Split modules when it improves ownership, build performance, isolation, or real reuse.
  • Test continuously. Test pure Kotlin logic, repositories, ViewModels, database migrations, and user-facing flows as those layers are introduced.
  • Measure before optimizing. Find the bottleneck, change one thing, and compare measurements instead of guessing.
  • Verify versions and policies at the time of use. Check compatibility across JDK, Gradle, AGP, Kotlin, Compose, and libraries. Recheck Google Play target API, privacy, permissions, and SDK policies before release.
  • Review AI-generated code. Run it, test it, inspect every relevant change, and understand it before merging. Generated code may use outdated APIs or violate the architecture.
