دليل تأسيسي مترابط يبدأ باللغة وأدواتها، ثم ينتقل إلى بنية المشروع والبناء، وينتهي بالتشغيل والتصحيح.

ما هي Kotlin؟ ولماذا ظهرت؟

Kotlin هي نقطة البداية لفهم الكود الذي سنكتبه داخل Android Studio، لكن استخدامها لا يقتصر على Android.

تعريف

Kotlin لغة برمجة حديثة، مفتوحة المصدر، وذات أنواع ثابتة (Statically Typed) طورتها شركة JetBrains. تدعم البرمجة كائنية التوجه (Object-Oriented Programming) والبرمجة الوظيفية (Functional Programming)، ويمكن استخدامها لبناء تطبيقات تستهدف منصات مختلفة.

صُممت لتقديم تجربة تطوير أكثر إنتاجية مع الحفاظ على التوافق مع منظومة Java، ومعالجة بعض نقاط الألم الشائعة في البرمجة، مثل كثرة الكود المتكرر ومشكلات التعامل مع القيم الفارغة.

المشكلة أو الاحتياج كيف تساعد Kotlin؟
Boilerplate Code تقدم صياغة مختصرة وميزات مثل data class لتقليل الكود المتكرر.
Null-related Errors توضح من خلال Type System ما إذا كان المتغير يقبل null.
Readability & Maintainability تساعد Syntax الواضحة والحديثة على قراءة الكود وصيانته.
Java Interoperability تسمح باستخدام Java Classes ومكتباتها والتدرج في نقل المشروعات.
Developer Productivity توفر أدوات لغوية تقلل الأعمال الروتينية وتدعم التطوير العملي.
ملاحظة

Kotlin ليست بديلًا يفرض التخلي عن Java؛ يمكن للغتين العمل معًا داخل المشروع نفسه.

الخصائص الأساسية مع أمثلة

أ) Concise Syntax — صياغة مختصرة

تقلل Kotlin الأكواد المتكررة. على سبيل المثال، يمكن تعريف Class لحمل بيانات المستخدم باستخدام data class:

User.kt — data class Kotlin 
data class User(
    val name: String,
    val age: Int
)

تتولى اللغة توليد وظائف شائعة للكلاس، مثل المقارنة النصية ونسخ البيانات، بدلًا من كتابتها يدويًا في الحالات المعتادة.

ب) Null Safety — التعامل الآمن مع القيم الفارغة

تفرق Kotlin بين نوع لا يقبل null ونوع يقبله. نضيف علامة ? إلى النوع لجعله Nullable.

NullSafety.kt — Safe Call وElvis Operator Kotlin 
val name: String = "Ahmed"       // Non-nullable
val nickname: String? = null     // Nullable

val length = nickname?.length    // Safe Call
val safeLength = nickname?.length ?: 0 // Elvis Operator

العامل ?. ينفذ الوصول إلى الخاصية فقط إذا لم تكن القيمة فارغة، بينما ?: يوفر قيمة بديلة عند وجود null.

انتبه

Null Safety تقلل احتمالات NullPointerException لكنها لا تمنع كل الحالات؛ فقد تظهر مشكلات عند التعامل مع Java APIs أو استخدام العامل !! أو بعض حالات التهيئة غير الآمنة.

ج) Interoperability — التوافق مع Java

يمكن لكود Kotlin استدعاء Java Classes ومكتباتها، كما يمكن لكود Java استدعاء Kotlin مع مراعاة قواعد الربط بين اللغتين. لذلك يمكن الاستفادة من مكتبات Java الحالية أو نقل أجزاء من مشروع قديم تدريجيًا.

د) Type Inference — استنتاج النوع

يستطيع Compiler استنتاج نوع المتغير من القيمة المسندة إليه، مع بقاء Kotlin لغة Statically Typed.

TypeInference.kt Kotlin 
val age = 25       // Int
val name = "Ahmed" // String
val price = 99.5   // Double

النوع معروف أثناء Compilation حتى عندما لا نكتبه صراحةً.

مقارنة Kotlin وJava

وجه المقارنة Kotlin Java
Syntax مختصر وحديث في حالات كثيرة. أكثر تفصيلًا في بعض الحالات.
Null Safety مدمجة في Type System. ليست مدمجة بالطريقة نفسها.
Type Inference مدعوم على نطاق واسع. مدعوم في نطاقات معينة، مثل var المحلي.
Data Classes data class مباشرة. تحتاج غالبًا إلى كتابة أو توليد كود، مع وجود record في إصدارات Java الحديثة.
Interoperability تستدعي Java بسهولة. يمكنها استدعاء Kotlin مع مراعاة قواعد التوافق.
Compilation لها Kotlin Compiler. لها Java Compiler.
Runtime تعمل على JVM عند استهداف JVM. تعمل على JVM.

هل Kotlin أسرع دائمًا من Java؟ لا. عند استهداف JVM تنتج اللغتان JVM Bytecode، ويعتمد الأداء على الكود والمكتبات والتحسينات وطبيعة العمل. وفي Android يتحول كود التطبيق إلى DEX ويعمل باستخدام Android Runtime (ART)، وليس JVM سطح المكتب.

أين تُستخدم Kotlin؟

المجال الاستخدام أمثلة أو بيئة التشغيل
Android تطوير تطبيقات الهواتف والأجهزة التي تعمل بنظام Android. Android SDK وJetpack وJetpack Compose.
Kotlin/JVM برامج وتطبيقات تعمل على Java Virtual Machine. JVM ومكتبات Java.
Server-side بناء Backend Services وREST APIs. Spring Boot وKtor.
Kotlin Multiplatform مشاركة أجزاء من الكود بين منصات متعددة. Android وiOS وDesktop وغيرها بحسب الدعم.

Kotlin Language وStandard Library وkotlinx Libraries

Kotlin Language

قواعد اللغة نفسها: Syntax، أنواع البيانات، المتغيرات، Functions، Classes، Null Safety وغيرها.

Kotlin Standard Library (kotlin-stdlib)

مكتبة أساسية توفر أدوات شائعة، مثل Collections وString Operations وExtension Functions وScope Functions مثل let وapply وalso.

kotlinx Libraries

مكتبات إضافية في منظومة Kotlin تضيف قدرات متخصصة، ولا تُعد جزءًا من قواعد اللغة نفسها.

  • kotlinx.coroutines: للتعامل مع Asynchronous Programming وCoroutines.
  • kotlinx.serialization: لتحويل البيانات من وإلى صيغ مثل JSON.
  • kotlinx.datetime: للتعامل مع التاريخ والوقت.
مثال

listOf("Ahmed", "Ali") تستخدم Function من Standard Library، بينما launch { ... } تأتي من مكتبة Coroutines عند إضافتها إلى المشروع واستيرادها.

Kotlin Multiplatform وCompose Multiplatform

Kotlin Multiplatform (KMP) تسمح بمشاركة الكود بين منصات متعددة. مثلًا، يمكن مشاركة Networking وData Models وBusiness Logic بين Android وiOS مع إبقاء واجهة المستخدم Native لكل منصة.

Compose Multiplatform إطار واجهات مستخدم يتيح مشاركة UI Code بين منصات مدعومة، بالإضافة إلى إمكانات مشاركة منطق التطبيق.

التقنية ما الذي يمكن مشاركته؟
Kotlin Multiplatform Business Logic وData وNetworking وغيرها.
Compose Multiplatform واجهة المستخدم أيضًا، على المنصات المدعومة.
ملاحظة

KMP وCompose Multiplatform موضوعان إضافيان، وليسا شرطًا للبدء في مسار Android Native. يمكن دراستهما بعد إتقان أساسيات Kotlin وAndroid.

JDK وما علاقته بتطوير Android؟

تحتاج عملية التطوير إلى بيئة تشغّل أدوات البناء، ومكونات Android SDK، وIDE لكتابة الكود وتشغيل التطبيق وفحصه.

تعريف

JDK = Java Development Kit، وهي مجموعة أدوات تطوير وتشغيل برامج Java. تتضمن JVM وأدوات مثل Java Compiler ومكتبات وأدوات مساعدة.

تعتمد أدوات البناء، ومنها Gradle، على JVM؛ لذلك يحتاج Gradle إلى JDK متوافق حتى يعمل. يمكن اختيار JDK مناسب أو JetBrains Runtime (JBR) الذي يأتي عادةً مع Android Studio، وفق متطلبات إصدار Gradle وAGP.

انتبه

لا تخلط بين JVM التي تشغّل Gradle على جهاز المطور وبين Android Runtime (ART) التي تشغّل تطبيق Android على الهاتف أو المحاكي.

Android SDK وSDK Manager

تعريف

SDK = Software Development Kit. Android SDK مجموعة الأدوات وواجهات البرمجة اللازمة لتطوير تطبيقات Android. أما SDK Manager فهو الأداة التي تتيح تثبيت مكوناته وتحديثها وإزالة ما لا تحتاج إليه.

المكون وظيفته
SDK Platforms Android APIs الخاصة بإصدارات النظام المختلفة.
SDK Build Tools أدوات تجهيز وبناء التطبيق، ومنها أدوات معالجة DEX والتغليف.
Platform Tools أدوات مثل ADB للتواصل مع الأجهزة.
Android Emulator تشغيل جهاز Android افتراضي.
System Images صور نظام Android التي يحتاجها Emulator.

Android Studio وIntelliJ IDEA

Android Studio هو IDE الأساسي لتطوير Android. يجمع محرر الكود وأدوات Gradle وSDK Manager وEmulator وLogcat وDebugger وأدوات تحليل الأداء.

IntelliJ IDEA بيئة تطوير من JetBrains تدعم Kotlin وJava، ومناسبة لتجربة اللغة وبناء برامج JVM ومشروعات غير مرتبطة مباشرةً بـ Android.

الأداة متى تكون مناسبة؟
Android Studio عند بناء تطبيق Android واستخدام Android SDK والمحاكي وأدوات Android.
IntelliJ IDEA عند تعلم Kotlin أو تطوير مشروع JVM أو Server-side لا يحتاج إلى أدوات Android.

من الإمكانيات المشتركة في IDEs: Code Completion وSyntax Highlighting وDebugging وRefactoring وإدارة ملفات المشروع.

Kotlin Playground

Project وModule

تعريف

Project هو الحاوية الرئيسية التي تضم إعدادات البناء والـ Modules والملفات المشتركة. أما Module فهو جزء من المشروع له مسؤولية وإعدادات بناء خاصة به.

Module محتمل المسؤولية
app تطبيق Android الرئيسي.
core كود مشترك أو أدوات أساسية.
data مصادر البيانات والتعامل معها.
domain Business Logic وقواعد العمل.

لا تحتاج إلى إنشاء كل هذه الوحدات في البداية؛ غالبًا يكفي Module واحد باسم app للتعلم.

مثال على Project Structure

يوضح المثال التالي شكلًا شائعًا لمشروع Android يحتوي على Module واحد باسم app: 

MyApplication/
├── app/
│   ├── build.gradle.kts
│   └── src/
│       ├── main/
│       │   ├── AndroidManifest.xml
│       │   ├── java/
│       │   │   └── com/example/myapplication/
│       │   │       └── MainActivity.kt
│       │   └── res/
│       │       ├── drawable/
│       │       ├── mipmap/
│       │       └── values/
│       ├── test/
│       └── androidTest/
├── gradle/
│   └── wrapper/
│       ├── gradle-wrapper.jar
│       └── gradle-wrapper.properties
├── build.gradle.kts
├── settings.gradle.kts
├── gradle.properties
├── gradlew
└── gradlew.bat
المجلد أو الملف وظيفته
app/ Module التطبيق.
src/main/ المصدر الرئيسي للتطبيق.
AndroidManifest.xml تعريف معلومات التطبيق ومكوناته والصلاحيات المطلوبة.
java/ مصادر Kotlin أو Java أو كليهما؛ اسم المجلد لا يعني أن المحتوى Java فقط.
res/ الموارد مثل الصور والنصوص والألوان والتخطيطات.
test/ اختبارات محلية تعمل عادةً على JVM الخاصة بجهاز التطوير.
androidTest/ اختبارات تحتاج إلى بيئة Android على جهاز أو محاكي.
build/ ملفات ناتجة عن عملية البناء، ولا تُضاف عادةً إلى Version Control.
ملاحظة

قد يختلف عرض Android Studio عن شكل المجلدات على القرص. Android View عرض تنظيمي، بينما Project View يعرض البنية الفعلية بصورة أقرب إلى نظام الملفات.

ملفات Gradle: أين توجد وماذا تفعل؟

تتحكم ملفات Gradle في تعريف وحدات المشروع وإعدادات البناء والخصائص العامة وإصدار Gradle المستخدم.

settings.gradle.kts

يوجد في جذر المشروع، ويحدد اسم المشروع والـ Modules المشاركة في البناء ومصادر البحث عن Plugins ومستودعات Dependencies وفق طريقة تنظيم المشروع.

settings.gradle.kts Gradle 
pluginManagement {
    repositories {
        google()
        mavenCentral()
        gradlePluginPortal()
    }
}

dependencyResolutionManagement {
    repositories {
        google()
        mavenCentral()
    }
}

rootProject.name = "MyApplication"
include(":app")

السطر include(":app") يضيف Module باسم app. ويمكن إضافة وحدات أخرى مثل include(":app", ":core").

build.gradle.kts

قد يوجد في جذر المشروع وعلى مستوى كل Module:

  • Project-level: إعدادات عامة وتعريف Plugins وإتاحتها للوحدات.
  • Module-level: إعدادات بناء الوحدة نفسها، مثل SDK Levels وDependencies وBuild Types.
app/build.gradle.kts — Module-level Gradle 
plugins {
    alias(libs.plugins.android.application)
}

android {
    namespace = "com.example.myapplication"

    compileSdk = 36

    defaultConfig {
        applicationId = "com.example.myapplication"
        minSdk = 23
        targetSdk = 36
    }
}
الإعداد المعنى
namespace مساحة الأسماء المستخدمة في المشروع، مثل أسماء R وBuildConfig.
applicationId الهوية الفعلية للتطبيق عند تثبيته ونشره.
compileSdk إصدار Android APIs المستخدم أثناء Compilation.
minSdk أقل إصدار Android يدعمه التطبيق.
targetSdk مستوى API الذي يستهدف التطبيق سلوكياته ومتطلبات التوافق الخاصة به.
ملاحظة

القيم الرقمية في المثال توضيحية؛ اختيار الإصدارات الفعلية يعتمد على توافق Android Studio وAGP وGradle ومتطلبات التطبيق.

gradle.properties

يحتوي على خصائص تتحكم في سلوك Gradle وبيئة البناء، مثل خيارات JVM والذاكرة وبعض إعدادات الأداء.

gradle.properties Gradle 
org.gradle.jvmargs=-Xmx2048m
org.gradle.parallel=true
kotlin.code.style=official

قد توجد نسخة على مستوى المشروع وأخرى ضمن إعدادات المستخدم. خصائص المستخدم يمكن أن تؤثر في أكثر من مشروع.

gradle-wrapper.properties

يوجد داخل gradle/wrapper/ ويحدد إصدار Gradle الذي سيستخدمه Wrapper.

gradle/wrapper/gradle-wrapper.properties Gradle 
distributionBase=GRADLE_USER_HOME
distributionPath=wrapper/dists
distributionUrl=https\://services.gradle.org/distributions/gradle-8.13-bin.zip

السطر الأهم هو distributionUrl لأنه يحدد توزيع Gradle المطلوب.

Gradle Wrapper وأهميته

تعريف

Gradle أداة Build Automation تنظم وتنفذ خطوات بناء المشروع. أما Gradle Wrapper فهو مجموعة ملفات وسكريبتات مرفقة بالمشروع لتشغيل إصدار Gradle المحدد له دون الاعتماد على وجود نسخة يدوية مناسبة على كل جهاز. 

gradle/
└── wrapper/
    ├── gradle-wrapper.jar
    └── gradle-wrapper.properties

gradlew       # Linux / macOS
gradlew.bat   # Windows
Terminal — بناء المشروع Bash 
# Linux / macOS
./gradlew build

# Windows
gradlew.bat build

يساعد Wrapper على توحيد إصدار Gradle بين أعضاء الفريق وبيئات CI/CD، وتقليل مشكلات اختلاف الإصدارات، وتسهيل إعداد المشروع لمطور جديد.

Build Lifecycle

يمر Gradle بثلاث مراحل رئيسية عندما يجهز عملية البناء وينفذها:

Initialization
اكتشاف المشاريع والـ Modules وقراءة settings.gradle.kts.
↓
Configuration
قراءة ملفات البناء وتجهيز المشاريع وتكوين Task Graph.
↓
Execution
تنفيذ المهام المطلوبة وفق علاقات الاعتماد بينها.

عند تنفيذ ./gradlew assembleDebug يحدد Gradle المشاريع، ويجهز المهام المطلوبة، ثم ينفذ المهام اللازمة لإنتاج Debug APK. لا يعني ذلك تنفيذ كل Task موجودة في المشروع.

Tasks وPlugins وDependencies

Tasks — المهام

هي وحدات العمل التي ينفذها Gradle، مثل Compilation وتشغيل الاختبارات وإنتاج ملفات التوزيع.

Task الوظيفة
clean حذف مخرجات البناء السابقة.
assembleDebug إنتاج Debug APK.
assembleRelease إنتاج Release APK وفق الإعدادات.
testDebugUnitTest تشغيل Unit Tests لوحدة Debug.
installDebug تثبيت نسخة Debug على جهاز متصل.
bundleRelease إنتاج Release AAB.
Terminal — عرض المهام وتنفيذ إحداها Bash 
./gradlew tasks
./gradlew :app:assembleDebug

Plugins — الإضافات

توسع قدرات Gradle. على سبيل المثال، يضيف Android Gradle Plugin إعدادات ومهامًا خاصة ببناء Android.

app/build.gradle.kts Gradle 
plugins {
    id("com.android.application")
}

Dependencies — الاعتماديات

مكتبات أو Modules يعتمد عليها المشروع لاستخدام وظائف جاهزة.

app/build.gradle.kts Gradle 
dependencies {
    implementation("com.example:some-library:1.0.0")
    testImplementation("junit:junit:4.13.2")
}
Configuration الاستخدام
implementation اعتمادية يحتاجها كود الوحدة.
testImplementation مكتبات للاختبارات المحلية.
androidTestImplementation مكتبات لاختبارات Android على جهاز أو محاكي.
debugImplementation مكتبات لنسخة Debug فقط.
ملاحظة

للتذكر: Plugin يضيف قدرة إلى Gradle، وTask تمثل عملية ينفذها، وDependency مكتبة أو وحدة يحتاج إليها المشروع.

دور JDK وGradle وKotlin Compiler وAGP معًا

المكون مسؤوليته
JDK / JBR توفير JVM وبيئة تشغيل Gradle والأدوات اللازمة.
Gradle تنظيم خطوات البناء وتنفيذ Tasks بحسب الاعتماديات.
Kotlin Compiler ترجمة Kotlin Source Code إلى Bytecode عند استهداف JVM.
Android Gradle Plugin (AGP) إضافة إعدادات ومهام Android إلى Gradle، مثل معالجة Resources وتجهيز APK/AAB.
Android SDK Build Tools المساعدة في تجهيز التطبيق، ومنها تحويل Bytecode إلى DEX باستخدام أدوات مثل D8.
ART بيئة تشغيل تطبيق Android على الجهاز.

عند الضغط على Build في Android Studio، يبدأ Gradle عبر Wrapper، ويستخدم JDK لتشغيل عملية البناء. يتولى AGP مهام Android، وتدخل Kotlin Compiler في ترجمة ملفات Kotlin وفق إعدادات المشروع، ثم تُستكمل خطوات DEX ومعالجة الموارد والتغليف.

انتبه

اختلاف الإصدارات: بدءًا من Android Gradle Plugin 9.0 يوجد دعم Kotlin مدمج في AGP، ولذلك لا يلزم عادةً تطبيق org.jetbrains.kotlin.android في إعدادات Android التقليدية التي تستخدم هذا الإصدار أو أحدث. في إصدارات AGP الأقدم قد يظهر Kotlin Gradle Plugin بصورة منفصلة. اتبع إعدادات الإصدار المستخدم ولا تخلط أمثلة إصدارات مختلفة.

الفرق بين Compile وBuild وRun

  • Compile: ترجمة الكود المصدري وفحصه وتحويله إلى صيغة وسيطة مناسبة للهدف، مثل JVM Bytecode عند استهداف JVM.
  • Build: عملية أوسع تشمل Compilation ومعالجة الموارد وتحويل الكود إلى DEX والتغليف والتوقيع بحسب نوع البناء وإعداداته.
  • Run: بناء التطبيق عند الحاجة، ثم تثبيته على Emulator أو جهاز حقيقي وتشغيله.

APK وAAB

APK — Android Package

حزمة Android يمكن تثبيتها مباشرة على جهاز متوافق. تستخدم للاختبار والتثبيت اليدوي وبعض أساليب التوزيع. مثال على اسم الملف: app-debug.apk

AAB — Android App Bundle

تنسيق نشر يحتوي على كود التطبيق وموارده، ويتيح لـ Google Play إنشاء APKs ملائمة لمواصفات الجهاز. مثال على اسم الملف: app-release.aab

APK AAB
حزمة قابلة للتثبيت مباشرة. تنسيق نشر تتم معالجته لإنتاج APKs.
مناسب للاختبار والتثبيت اليدوي. يستخدم عادةً عند النشر عبر Google Play.
يمثل الحزمة التي ستُثبت على الجهاز. يسمح بإنشاء حزم ملائمة لمواصفات الجهاز.
انتبه

AAB لا يُثبت مباشرة بالطريقة المعتادة مثل APK. يجب أن يعالجه متجر أو أداة مثل bundletool لإنتاج ملفات APK قابلة للتثبيت.

التشغيل على Emulator

تعريف

Emulator جهاز Android افتراضي يعمل على الكمبيوتر. أما AVD = Android Virtual Device فهو تعريف الجهاز الافتراضي، مثل نوع الجهاز وحجم الشاشة وإصدار Android وصورة النظام.

  1. افتح Device Manager في Android Studio.
  2. أنشئ Virtual Device جديدًا.
  3. اختر نوع الجهاز، مثل Pixel.
  4. اختر System Image مناسبة لإصدار Android المطلوب.
  5. شغّل Emulator.
  6. اختره من قائمة الأجهزة في Android Studio ثم اضغط Run.

يفيد Emulator في اختبار أحجام الشاشات وإصدارات Android وحالات الاستخدام المختلفة دون الحاجة إلى هاتف فعلي لكل تجربة. للمزيد من التفاصيل: Android Emulator في التوثيق الرسمي.

التشغيل على جهاز حقيقي

  1. افتح Settings في الهاتف، ثم About Phone.
  2. اضغط على Build Number عدة مرات لتفعيل Developer Options؛ وقد تختلف الخطوات بحسب الشركة المصنعة.
  3. افتح Developer Options وفعّل USB Debugging.
  4. صِل الهاتف بالكمبيوتر عبر USB.
  5. وافق على رسالة السماح بالاتصال من الكمبيوتر على الهاتف.
  6. اختر الجهاز من Android Studio واضغط Run.

يمكن أيضًا استخدام Wireless Debugging على الأجهزة والإصدارات المدعومة. من الأفضل الاختبار على Emulator وجهاز حقيقي متى أمكن؛ لأن الأداء والكاميرا وGPS وBluetooth والحساسات قد تختلف عن المحاكي.

Logcat

تعريف

Logcat نافذة تعرض رسائل التطبيق والنظام أثناء التشغيل، وتساعد على متابعة سلوك التطبيق والأخطاء والاستثناءات (Exceptions).

MainActivity.kt — كتابة رسائل إلى Logcat Kotlin 
import android.util.Log

fun onButtonClicked() {
    Log.d("MainActivity", "Button Clicked")
    Log.e("MainActivity", "Failed to load data")
}
الدالة المستوى الاستخدام
Log.v() Verbose تفاصيل كثيرة.
Log.d() Debug معلومات أثناء التطوير.
Log.i() Info معلومات عامة.
Log.w() Warning تحذيرات تستحق الانتباه.
Log.e() Error أخطاء.

لفتح Logcat، شغّل التطبيق ثم افتح نافذة Logcat من Tool Windows، وحدد الجهاز والتطبيق، واستخدم Filters أو Search للوصول إلى الرسالة المطلوبة. شكل النافذة موضح في صفحة Logcat في التوثيق الرسمي.

Debugger وBreakpoints

تعريف

Debugger يسمح بإيقاف التنفيذ مؤقتًا وفحص حالة التطبيق ومتابعة الكود خطوة بخطوة. أما Breakpoint فهي نقطة توقف يضعها المطور على سطر معين.

Cart.kt Kotlin 
fun calculateTotal(price: Int, quantity: Int): Int {
    val total = price * quantity  // Set a breakpoint here
    return total
}

ضع Breakpoint بالضغط في الهامش بجوار رقم السطر، ثم شغّل التطبيق باستخدام Debug. عند الوصول إلى السطر المحدد سيتوقف التنفيذ مؤقتًا.

Step Over وStep Into وWatches

Cart.kt Kotlin 
fun calculateTotal(price: Int, quantity: Int): Int {
    val total = price * quantity
    return total
}

fun main() {
    val result = calculateTotal(100, 5)
    println(result)
}
Output 
500
الأمر ما الذي يفعله؟
Step Over ينفذ السطر الحالي، بما في ذلك استدعاء الدالة، ثم ينتقل إلى التالي دون الدخول إلى تفاصيل الدالة.
Step Into يدخل إلى الدالة المستدعاة لمتابعة تنفيذها من الداخل.
Watches تراقب قيمة متغير أو Expression أثناء توقف Debugger.

يمكن إضافة Expressions مثل price أو quantity أو price * quantity إلى Watches ومتابعة نتائجها عندما تكون صالحة في السياق الحالي.

Compiler Messages

تظهر رسائل Compiler عندما توجد مشكلة تمنع ترجمة الكود، بينما قد تعرض نافذة Build أيضًا رسائل من Gradle أو Plugins أو SDK أو Dependency Resolution.

Main.kt — لا يُترجم عمدًا Kotlin 
val age: Int = "25"
Compiler 
Type mismatch
Required: Int
Found: String
الرسالة المعنى المحتمل
Syntax Error خطأ في صياغة الكود.
Type Mismatch عدم توافق أنواع البيانات.
Unresolved Reference اسم أو رمز غير معروف في السياق الحالي.
Redeclaration إعادة تعريف اسم موجود في النطاق نفسه.
Could not resolve dependency مشكلة في حل الاعتمادية أو الوصول إلى المستودع، وليست بالضرورة خطأ Kotlin.

يمكن قراءة الرسائل من Build Output أو Problems داخل Android Studio. ليس كل فشل Build ناتجًا عن Kotlin Compiler؛ فقد يكون السبب Gradle أو Plugin أو Dependency أو Android SDK.

Stack Trace

يعرض Stack Trace تسلسل استدعاءات الدوال التي قادت إلى حدوث Exception. مثال مبسط:

Logcat 
FATAL EXCEPTION: main

java.lang.NullPointerException

at com.example.app.MainActivity.onCreate(MainActivity.kt:24)
at android.app.Activity.performCreate(...)
الجزء المعنى
FATAL EXCEPTION حدث استثناء أدى إلى إنهاء العملية أو انهيار التطبيق.
NullPointerException نوع الاستثناء.
MainActivity.kt:24 اسم الملف ورقم السطر في كود المشروع.
onCreate() الدالة التي ظهر الخطأ أثناء تنفيذها.

ابدأ بنوع Exception، ثم ابحث عن أول سطر يشير إلى كود مشروعك. افتح الملف ورقم السطر وافحص القيم والسياق. وإذا ظهر Caused by فقد يشير إلى السبب الأصلي وراء الاستثناء الظاهر.

Compile-time وRuntime وLogical Errors

النوع متى يظهر؟ مثال أين نبحث؟
Compile-time Error أثناء Compilation، ويمنع نجاح الترجمة عندما يكون الخطأ مانعًا. val age: Int = "25" Compiler Messages وBuild Output.
Runtime Error أثناء تنفيذ التطبيق بعد نجاح Compilation. استدعاء length على قيمة فارغة باستخدام !!. Logcat وStack Trace وDebugger.
Logical Error عندما يعمل الكود لكنه يعطي نتيجة غير صحيحة. استخدام الجمع بدل الضرب لحساب الإجمالي. الاختبارات ومراجعة النتائج وDebugger.

مثال على Runtime Error

Main.kt — Runtime Error Kotlin 
fun main() {
    val name: String? = null
    println(name!!.length)
}

يقبل Compiler الكود لأن !! تطلب التعامل مع القيمة على أنها غير فارغة، لكن التنفيذ يفشل عندما تكون القيمة فعلًا null، فيحدث NullPointerException.

مثال على Logical Error

Cart.kt — Logical Error Kotlin 
val price = 100
val quantity = 5

val total = price + quantity // Logical error: adds instead of multiplying
val correctTotal = price * quantity

الكود الأول صحيح من ناحية Syntax والأنواع، لكنه لا ينفذ المعادلة المطلوبة. لذلك لا تؤدي كل الأخطاء إلى Crash.
